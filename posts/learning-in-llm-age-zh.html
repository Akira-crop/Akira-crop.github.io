LLM 时代，如何继续学习：把 AI 当导师，而不是答案机器（译）

2026年10月7日
LLM学习方法编程学习AI工具翻译
本文是 Oğuzhan Olguncu 文章 How to keep learning in the age of LLMs 的中文翻译。

原文发表于 2026 年 10 月 4 日。译文保留作者的第一人称叙述、代码示例和项目名称，少量调整了段落和标点，方便中文阅读。

我想聊聊，在 LLM 时代我是怎么继续学习新东西的，因为这件事变得很难。

LLM、AI、智能体，不管你怎么称呼它们，都可以一次性把事情做完，也会消灭“把事情做错”的全部乐趣。我主要想谈编程，但我觉得这套方法也适用于其他领域。

过去，我们学习框架、编程语言和设计模式，往往先做错一些事情，再从错误里学到教训。可现在一切都太快了，我们不愿意把时间花在“做错”上，尽管从长远来看，这样做反而更有益。大脑正是通过这种挣扎学会新东西的。

说实话，我自己也有这个问题。以前我会花很多时间苦练，但现在总觉得这样没意义，因为你想要什么，LLM 都可以直接给你。那些念头把我带到了现在：我的学习遇到了瓶颈，同时又因为工作和兴趣，需要继续学更多东西。

下面就是我重新找回学习方法的过程。

让 LLM 教你，而不是替你完成

当时我正在读一篇叫作 Bitcask 的论文。如果你对编程感兴趣，又还没读过，我建议你找来看看。它非常轻量，即使你不是经验丰富的程序员也能读懂，因为里面的概念很容易消化，只要愿意动手，实现起来也不难。

读完之后，我想在完全没有 LLM 帮助的情况下把它实现出来。大部分时候我确实做到了。后来我在代码里的某个地方卡住了，想使用 LLM，但这一次，我没有让它替我写出卡住的那一部分，而是让它把相关概念解释清楚，好让我自己完成。

然后我意识到：我可以让 LLM 教我东西，但不让它把所有答案都直接给出来。

同时，它还能替我处理那些机械劳动，让我不至于因为无聊而放弃。比如，你想通过构建一个聊天应用来学习某个主题。这个应用需要服务器和客户端，而你真正想练习的只是服务器部分。如果客户端并不是你感兴趣的内容，为什么要让实现客户端这件事消耗掉你的动力？

这正是 LLM 能帮上忙的地方。你可以把测试、工具链和可视化交给它处理。我的意思不是这些东西没用，只是如果它们不是你想学习的重点，就不必亲自把每一部分都做一遍。

后来我开始观察其他人是怎么做的，发现了一个叫作 “socratic-code-mentor” 的技能。它不会直接把答案递给你，而是提出合适的问题，让你自己走到答案那里。也正因为如此，学到的东西才会留下来。

下面是一个简化的例子。

我： 我觉得这个求和结果应该是 6，但得到的是 NaN：

js
const nums = [1, 2, 3];
let sum = 0;
for (let i = 0; i <= nums.length; i++) sum += nums[i];
console.log(sum); // NaN

LLM： nums 里有几个元素？最后一个索引是多少？

我： 有 3 个元素，所以最后一个索引是 2。

LLM： 你的循环会让 i 取哪些值？

我： 0、1、2、3……等等。nums[3] 是 undefined，而 6 + undefined 就是 NaN。

LLM： 对。看这里：

text
index:   0  1  2  3
nums:   [1, 2, 3] undefined
i:       ▲  ▲  ▲  ▲  ← 多走了一步

你会怎么修复？

我： 使用 i < nums.length。

所以，LLM 没有直接告诉我“你的循环多执行了一次”。它只是问了几个问题，又画了一张图，最后是我自己找到了 bug。

我不会忘记这个错误，因为我被迫亲自把它想通了。

我们是通过推导和解决问题来学习的，而不是靠接受别人告诉我们的每一个事实。《Make It Stick》这本关于学习心理学的书说得很好：

当你在看到解决方法之前，先被要求努力解决一个问题，那么之后看到的解法会学得更好，也会记得更久。

甚至我最要好的朋友兼 CTO，也经常和我玩这种“思维游戏”。

我问他：“我们为什么不按 X 的方式做？”

他会回答：“你为什么觉得我们应该按 X 的方式做？”

我解释自己的理由，他再针对我的回答继续提问，最后我往往会自己推导出一个靠谱的答案。而且这个答案会留下来。

所以，你还是得稍微锻炼一下自己的大脑。这正是那个技能在做的事情：让你不断追问。

先做计划，降低开始的阻力

第二个问题是如何保持状态，而这需要纪律。

如果你在做一个不简单的项目来学习某个主题，不可能一夜之间完成。因此，提前规划好要达成的目标，你就不必每次都浪费时间思考下一步该做什么。

否则，你很可能会在下一次开始学习时，对着空白屏幕发呆 30 分钟。至少我会这样。人在没有动力或缺乏自律时，很容易拖延。

理想状态是：你坐到电脑前，对 LLM 说一句“我们继续”，它就能从你上次停下的地方接着往下走。

出人意料的是，LLM 非常擅长帮你列出目标清单。

假设你想做一个玩具版的 LevelDB，换句话说，就是做一个 LSM-tree。如果你不是程序员，却还读到了这里，我先说声抱歉。

你可以让 LLM 把这个项目拆成若干阶段，每个阶段都设定清晰的目标。这样，每次开始新的学习会话时，你都只需要勾掉一个方框。

在完成 Bitcask 之后，我想挑战更难、也更偏数据库的东西，于是开始构建一个 LSM-tree，并把它叫作 tinylsm。我大概还会继续做各种 tiny-xyz 项目。

下面是我为 tinylsm 使用的 PLAN.md 的删节版：

markdown
# tinylsm —— 构建计划

**黄金规则：** 每个阶段结束时，都必须得到一个能工作的系统和全部通过的测试。
不要同时推进两个半成品功能。

## 阶段 2 —— WAL（预写日志）

**目标：** 能够从崩溃中恢复。每次写入都先进入日志，再写入内存，
这样发生崩溃后，我们可以重放日志，不会丢失已经完成的写入。

**步骤：**

1. 编码和解码一条记录。
2. 把记录追加到文件。
3. 启动时重放文件；如果最后一条记录只写了一半，要正常停止。

**完成标准：** 在写入过程中杀掉进程，重新启动后，每一条已经完成的写入都能恢复。

**陷阱：** 崩溃可能会把最后一条记录截断。这是预期情况，不代表数据损坏。

## 进度

- [x] 阶段 1 —— 跳表
- [x] 阶段 2 —— WAL
- [ ] 阶段 3 —— Memtable
- [ ] ...

每个阶段都有同样的四个部分：目标、可执行的小步骤、能够实际检查的“完成标准”，以及一个提前提醒你的陷阱。

底部的清单就是“我们继续”这句话的关键。LLM 读完它，就知道你目前进行到了哪里。

这样一来，你就不用再消耗意志力决定下一步做什么了。启动一次学习所需要的力气，比想象中还大。现在更是如此，因为 LLM、短视频和其他东西一直在提供即时的多巴胺刺激。

我们想让事情立刻完成，而且越快越好。一个计划恰好能给你想要的东西。即使已经很疲惫，你也可以只完成一点点，然后把它当作一个小胜利。

用间隔练习让知识留下来

这种工作方式其实能教会你更多东西，因为你会在几天、几周的时间里，以短时段反复回到同一个项目。

这让我想起禅师铃木俊隆关于“在雾中行走”的比喻：你不会立刻意识到自己被雾打湿，但一点一点地，你确实会湿透。

心理学家把这叫作间隔练习。两次学习之间保留一点遗忘，会迫使大脑重新把知识提取出来，而这种提取本身正是让知识牢固的原因。

到这里，我们已经讲了两件事：如何正确使用 LLM 来学习，而不是让它一次性把答案做完；以及如何提前计划，避免自己永远拖延。

但还缺一件事。

让进展变得可见

我个人在得到可视化反馈时，会更享受正在做的事情。它可以是一个做得很粗糙的 UI，也可以是一个 REPL，随便什么都行。

可视化反馈会迫使我留在游戏里，也会让我继续好奇接下来会发生什么。

在 tinylsm 里，我让 LLM 帮我做了一个小型 REPL。通过它，我可以往数据库里填数据，看着表不断堆积，再对读取性能做基准测试：

text
tinylsm> bench
  miss latency vs L0 height
    88 tables ██████████████████████████████ 174.9µs
     1 table  ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░   1.7µs

说真的，看到自己写的压缩代码让读取速度提升了 100 倍，确实给了我继续做下去的动力。

我建议你下一个大项目也这样做。文章最后我会分享的那个技能也能帮助你完成这件事，不过你也可以自己发挥想象。

有了 LLM，你可以构建任何能让自己继续走下去的东西。

把下一个项目选得更难一点

最后一条建议：把下一个项目定得有野心一些。

在 LLM 出现以前，要实现一个 LSM-tree 这样的东西，意味着你需要翻很多 GitHub 仓库，再去阅读几本书中特定章节的特定部分。

现在，你只需要对 LLM 说：“我想学习 XYZ 是怎么工作的。”它就会帮你研究，找到你需要的各种材料。

从某种意义上说，事情变简单了，但我们也变懒了。我猜以前一直如此。人就是喜欢偷懒。

结语

给像我一样懒的人做一个 TL;DR：

  • 不要让 LLM 直接给你答案。把它当作导师。
  • 把测试、工具链之类的机械劳动交给 LLM。
  • 提前和 LLM 一起做计划，用尽可能少的意志力保持动力。毕竟我们现在剩下的意志力已经不多了。
  • 让进展可见：做一个 REPL、一张图表，或者任何能让你继续留在项目里的东西。
  • 追求小胜利。即使每天只能工作 30 分钟，也比连续猛冲两天、然后十天不碰要好。稳定比爆发更重要。
  • 保持好奇，试着学习那些超出自己当前能力范围的东西。即使你不是最聪明的人，也可以对 LLM 说 100 次“我不懂”，让它再解释一遍。所以，不要只满足于简单的东西。

我使用的技能叫 socratic-code-mentor。我找到了它的原版，然后按照自己的学习方式重新改造了一遍。你可以拿去使用，再把它改成适合自己的样子。

最后，用一句我努力践行的话收尾：

“当你做一件事时，要像一堆好的篝火那样，把自己彻底燃烧，不留下自己的痕迹。”

——铃木俊隆
