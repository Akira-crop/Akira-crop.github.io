CS61B Lecture 2 笔记:类与对象,以及贯穿全讲的一对判断——数据属于谁,行为由谁执行

2026年9月7日
CS61BJava面向对象学习笔记

课程:UC Berkeley CS61B(Spring 2026),Lecture 2 "Defining and Using Classes, Lists"。

Lecture 1 建立的是"程序怎么组织、怎么运行"的模型;Lecture 2 往前推了一步:语言自带的 int、double 不够用，程序怎么定义"狗""行星"这样的新类型? 答案是类。

这一讲语法点不少——构造器、this、实例方法、静态方法、静态变量、List——但全部围绕一对判断展开:

这份数据属于谁(每个对象一份，还是全类共享)?这个行为由谁执行(某个具体对象，还是类本身)?

这两个问题答得出来，static 什么时候该写、什么时候不该写，基本都能自己推导出来，不用背规则。笔记就按这条线组织，最后落到本讲最重要的思想:接口与实现的分离。

一、为什么需要类：从散落的变量到绑定的整体

不用类，表示两只狗大概是这样:

java
int dog1Size = 5;
int dog2Size = 100;

void makeDogNoise(int size) { ... }

两只狗还行。一旦每只狗还有名字、年龄、主人，就得靠命名约定维持"哪些变量属于同一只狗"——这种对应关系极其脆弱，本质上是程序员在用纪律模拟语言本该提供的结构。

类做的事情，就是把同一事物的状态和行为绑在一起:

java
class Dog {
    int size;

    Dog(int size) {
        this.size = size;
    }

    void makeNoise() {
        if (size < 10) {
            IO.println("yip");
        } else if (size < 30) {
            IO.println("bark");
        } else {
            IO.println("arrooooooo!");
        }
    }
}

这里有个值得想一层的点:类定义之后，Dog 就成了和 int、String 平起平坐的类型。 Lecture 1 说"类型是 Java 里所有代码实体的固有属性",现在类型集合可以由程序员自己扩充了——静态类型系统随即开始检查新类型:hugeDog.size = 5; 合法，而 hugeDog.name = "Frank"; 编译错误，因为 Dog 没有 name 字段。Java 不允许对象在运行中临时长出类里没声明的东西(这一点和 Python 差别很大——Python 的对象可以随时挂新属性，自由，但也意味着拼错字段名不会有人提醒你)。

类与对象的关系，一句话:类是类型定义，对象是运行时的实例。 "图纸与房子"的类比可以帮助入门，但别推太远——类不是"装对象的容器",它定义的是结构和行为规则，每个对象按规则各有一份状态。所以:

java
Dog a = new Dog(5);
Dog b = new Dog(40);
a.size = 8;   // 只影响 a 所指的对象,b.size 仍是 40

共享的是字段的结构,不是字段的值。这个区分是后面理解静态变量的对照组。

二、构造器：对象如何开始存在

java
Dog(int size) {
    this.size = size;
}

构造器的特征：名字与类名相同、没有返回类型(连 void 都不能写)、在 new 时执行、负责建立初始状态。

为什么不能有返回类型?可以理解成语言层面的刻意区分：构造器不是"被调用来算一个值"的方法，它是 new 表达式的一部分——new Dog(5) 整体做的事是"创建对象 + 初始化 + 交出这个对象"。一旦允许写返回类型，这个语义就模糊了。顺手记住推论:void Dog(int size) 不是构造器，只是一个恰好和类同名的普通方法。

Dog d = new Dog(5) 是三个动作的合写,拆开看很有价值:

java
Dog d;               // 声明：只有一个类型为 Dog 的变量，还没有对象
new Dog(20);         // 实例化：对象确实创建了，但没保存引用，之后够不着它
d = new Dog(5);      // 实例化 + 赋值

"声明变量 ≠ 创建对象"是初学者最容易塌掉的一块地基。没有 new,就没有新对象。

this 与参数遮蔽

构造器推荐写成 this.size = size; 而不是换个参数名，原因是同名参数会遮蔽字段:

java
Dog(int size) {
    size = size;   // 能编译，但两边都是参数，字段没赋值——危险的逻辑错误
}

this.size 是"当前正在构造的这个对象的字段",右边的 size 是参数。这个 bug 的阴险之处在于编译器完全放行：类型都对，语义全错。这又一次印证了 Lecture 1 的结论——编译通过只代表类型合法。

三、实例方法与 this：每个调用都有一个隐含的接收者

grow()、makeNoise() 没有 static,是实例方法，调用必须挂在某个对象上:

java
Dog maya = new Dog(9);
maya.grow();       // maya 所指对象的 size 变成 10
maya.makeNoise();  // 输出 bark

实例方法执行期间，this 指代调用它的那个对象。看这个更完整的例子:

java
Dog maxDog(Dog otherDog) {
    if (otherDog.size > this.size) {
        return otherDog;
    }
    return this;
}

a.maxDog(b) 执行时:this 是 a,otherDog 是 b。换句话说，实例方法调用 a.f(b) 里有两个"输入":隐含的接收者 a,和显式的参数 b。 看懂这一点，this 就没什么神秘的了。

this 什么时候能省?字段访问无歧义时(size 就是 this.size);两种场合不能省：参数遮蔽(见上节),和 return this——这里要的是"当前对象"这个值本身。

四、静态方法：没有接收者的类级操作

同一个"比较两只狗",也可以写成静态方法:

java
static Dog maxDog(Dog d1, Dog d2) {
    if (d1.size > d2.size) {
        return d1;
    }
    return d2;
}

调用:Dog.maxDog(a, b)。

两种设计的对照:

定义调用隐含对象
实例方法Dog maxDog(Dog other)a.maxDog(b)this == a
静态方法static Dog maxDog(Dog a, Dog b)Dog.maxDog(a, b)无 this

关键认知:静态方法的本质不是"不修改数据",而是"调用时没有隐含的当前对象"。 由此推出两个结论:

  1. 静态方法不能直接读实例字段——IO.println(size); 编译错误，因为根本回答不了"哪只狗的 size";
  2. 但它可以通过显式参数接触对象——static void printSize(Dog d) 完全合法。

判断一个方法该不该是实例方法，标准问题只有一个:这个行为是否天然由某个具体对象执行、且需要它的状态? "这只狗长大一磅"是;"比较两只狗"没有天然执行者，两种设计都成立——区别只在接口表达:Dog.maxDog(a, b) 把它建模为类级工具操作,a.maxDog(b) 建模为"a 与 b 比较"。选哪种取决于哪种更贴合领域语义，而不是"哪个能编译"。

顺带划清两个边界：

  • 静态方法不是"全局函数",它仍然属于某个类;Math.round(5.6) 就是典型——四舍五入不需要先 new Math()。
  • Java 允许 a.maxDog(a, b) 这样通过实例调静态方法，但这是风格事故：让读者误以为方法依赖接收者。静态成员，用类名访问。

五、静态变量：全类一份的共享状态

java
class Dog {
    int size;                              // 每个对象一份
    static String binomen = "Canis familiaris";  // 全类共享一份
}

和第一节对照着看就清楚了：实例变量是"结构共享、值各有一份",静态变量连值都只有一份——所有对象观察到的是同一个变量。访问用 Dog.binomen,写 maya.binomen 即使能编译也掩盖了共享的事实。

真正值得展开的是：为什么可变的静态变量危险? 如果程序的任何角落都能改写它，那么一个函数的行为就可能取决于远处代码曾经做过什么——推理一个类不再只需要看这个类。这本质上是作用域问题：共享范围越大，理解和测试的成本越高。

所以实践中：本意是常量的，写成 static final String BINOMEN = "..."(final 只能赋值一次，全大写是惯例);确实需要可变共享状态的(比如统计创建了多少对象),不是不能用，但要有明确目的，并把写入位置控制在少数地方。

六、两个补丁：public 与 Java 25 入口

public 现阶段只需一个最小模型:它是访问权限修饰符，写在类、构造器、字段、方法前，表示可被更广泛的代码访问。两个错误结论都别急着下："public 没作用"(跨类跨包时很重要，只是当前例子体现不出);"字段都该 public"(教学方便而已，真实设计常用 private 保护内部表示——这件事后面会和"接口与实现"那条线汇合)。

Java 25 简化入口是 Spring 2026 和旧资料最容易打架的地方:

java
void main() {
    IO.println("hello world");   // 简化写法,2026 课堂常用
}
java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("hello world");   // 传统写法,HW 和现实世界的主流
    }
}

两种都要会读。概念没变——程序总要有个入口，只是 Java 25 给初学者提供了更轻的语法。看懂旧资料、在线评测和真实项目，传统写法绕不开。

七、List：一个引出整门课中心问题的例子

有了对象，自然的需求是"装很多对象"。List 是有序序列：尾部添加、按索引读、删元素、查大小。

java
import java.util.ArrayList;
import java.util.List;

List<String> words = new ArrayList<>();
words.add("data");
words.add("structure");
words.set(0, "Data");
IO.println(words.get(1));  // structure
IO.println(words.size());  // 2

几个速记点：List/ArrayList 在 java.util 包里，需要 import;读取用 get(i) 不是 [],长度用 size() 不是 length;泛型参数不能是基本类型,List<int> 不行，得 List<Integer>。(2026 课堂先用 Java 4 时代的 raw List 做演示，纯粹为了突出接口和实现的区别，自己的新代码别照抄——raw 类型等于主动关掉编译器的类型检查。)

八、接口与实现：本讲思想的高地

java
List<String> words = new ArrayList<>();

这一行是 Lecture 2 最值得停下来咀嚼的代码。左右两边回答的是两个不同的问题:

层次例子回答的问题
抽象数据类型(接口)List<String>能做什么? add、get、remove、size……
具体实现new ArrayList<>()怎么做到? 内部用什么结构和算法

new List() 编译错误，原因就是 List 只是一份"能力约定",本身没有完整实现。换成 new LinkedList<>(),使用方照样调 add、get、remove——但内部表示和各操作的成本完全不同。

为什么要分这两层?这条线会直接通到整门课的核心:

  1. 替换实现:代码只依赖 List 约定，换实现不用大改;
  2. 隐藏细节:调用者不需要知道数组怎么扩容、链表节点怎么连;
  3. 比较性能:同一操作在不同实现上成本不同——这正是数据结构课要分析的东西;
  4. CS61B 后面会亲手实现 SLList、AList,就是在回答"同一个 List 抽象，可以有哪些实现，各自牺牲什么换来什么"。

但也要给一个边界，别把经验当定律:"变量总声明成接口类型"不绝对成立——如果真需要某个实现独有的操作，就得用具体类型。准确的说法是:接口降低替换成本，但不保证所有可观察性质(尤其是性能)完全相同。 数据结构的选择由操作模式决定，不由名字决定——这个原则现在就该建立，复杂度分析的结论表后面再背。

九、一次综合追踪：把整讲的机制串起来

java
class Dog {
    int size;
    static int dogCount = 0;

    Dog(int size) {
        this.size = size;
        dogCount += 1;
    }

    void grow() {
        size += 1;
    }

    static Dog maxDog(Dog a, Dog b) {
        if (a.size > b.size) { return a; }
        return b;
    }
}

void main() {
    List<Dog> dogs = new ArrayList<>();
    Dog x = new Dog(9);
    Dog y = new Dog(12);
    dogs.add(x);
    dogs.add(y);
    x.grow();
    Dog larger = Dog.maxDog(dogs.get(0), dogs.get(1));
    IO.println(larger.size);
    IO.println(Dog.dogCount);
}

追踪：x 的狗 size=9,共享计数变 1;y 的狗 size=12,计数变 2;两个对象进 List;x.grow() 把第一只改成 10;get(0) 取出 10、get(1) 取出 12,静态方法返回第二只——输出 12 和 2。

这段代码用到了本讲几乎所有机制：实例变量(每只狗自己的 size)、静态变量(共享的 dogCount)、构造器里的 this、实例方法、静态方法、接口声明 + 实现实例化。注意还有一个被暂时按下不表的问题:x.grow() 之后，为什么从 List 里 get(0) 取出来的也是 10?因为变量和 List 里存的都是引用,不是对象副本——这是 Lecture 3 的主题，也是理解 null、别名和对象共享修改的钥匙。

总结：一张逻辑链

code
为什么需要类:内置类型不够 → 程序员自定义类型，状态与行为绑定
   ↓
对象如何诞生:new 创建 + 构造器初始化(this 区分字段与参数)
   ↓
行为由谁执行:实例方法有隐含接收者 this;静态方法没有 → 属于类
   ↓
数据属于谁:实例变量每对象一份;静态变量全类共享(可变共享状态慎用)
   ↓
抽象与实现分离:List 约定能力,ArrayList/LinkedList 提供机制
   ↓ (通往整门课)
同一抽象的不同实现，正确性/性能如何取舍——数据结构课的中心问题

一句话压缩:类让程序员定义新类型；实例成员属于对象、静态成员属于类；List 与 ArrayList 的分离则第一次展示了"约定能力"与"提供机制"可以独立变化。 全讲的语法都能从"数据属于谁、行为由谁执行"这两个问题推出来。
