CS61B Lecture 1 笔记:从已有语言迁移到 Java,真正该建立的是哪几个模型

2026年9月7日
CS61BJava学习笔记

课程：UC Berkeley CS61B(Spring 2025),Lecture 1 "Intro, Java"。

先说一个判断：这一讲的知识点单拆出来都很简单——HelloWorld、变量、while、方法。但官方想让你建立的不是这些语法点，而是三个模型：Java 程序的结构模型(代码放在哪、从哪开始执行)、编译运行模型(.java 怎么变成运行结果)、静态类型模型(编译器在运行前帮你检查什么、又检查不了什么)。

这篇笔记就按这三条线组织，最后补一节方法和一节风格。有 Python 或其他语言基础的话，重点看每节的对比部分——那才是这一讲真正的新信息。

一、前置认知：这门课不教 Java

课件里写得很明确：Java 只是工具，课程的目标是数据结构设计、效率分析、大型程序的测试与调试。这决定了它的讲法——语法过得非常快，因为默认你已经会变量、循环、函数、递归。

这个定位对学习策略有直接影响：如果卡在 Java 语法上，说明该做的是补齐语法(Homework 0A 就是干这个的);如果卡在循环递归本身，那问题不在 Java,得回去练小程序。两种情况用同一种方法(硬跟课程)都会很痛苦。

二、结构模型：为什么 Java 程序长这个样子

对比最能说明问题。Python:

python
print("hello world")

Java:

java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("hello world");
    }
}

表面看是"啰嗦",实质是设计取向不同：Java 要求程序员把代码归属和类型显式写出来。三行的小程序里这是负担，几千个类的项目里这是刚需——编译器、IDE、其他程序员都靠这些显式信息工作。

拆解这段代码，有一个理解角度很重要：入口方法是一份协议，不是一个普通函数。

  • public class HelloWorld——类是代码的容器；公共类名必须和文件名一致(HelloWorld.java)。
  • public static void main(String[] args)——JVM 启动时按这个固定签名找入口。static 表示不需要先创建对象就能调用；main 是规定死的名字，改了就不是入口了。
  • System.out.println——标准输出并换行；print 不换行。

所以这一层的正确姿势是：把 public static void main(String[] args) 当固定模板先背下来，public、static、类的完整含义后面几讲自然会展开，现在追究只会拖慢进度。

两个补充认知：

  1. 结构靠 {},不靠缩进。 缩进不改变语义，但错误的缩进会让人误判结构——所以风格上缩进依然必须一致。
  2. "所有代码必须在类里"只是入门近似。Java 源文件还可以声明接口、枚举、记录，但可执行语句确实不能像 Python 那样散落在顶层。

三、编译运行模型：两条命令之间发生了什么

bash
javac HelloWorld.java   # 编译:.java → .class(字节码)
java HelloWorld          # 运行:JVM 加载类的字节码，找 main 执行
text
HelloWorld.java  --javac-->  HelloWorld.class  --java/JVM-->  执行

这条链上每个环节都有值得记住的点：

.class 是字节码，不是机器码，也不是源码。 它是 JVM 的指令格式——正因为有这个中间层，同一份编译产物才能在任何平台的 JVM 上跑。这就是 "write once, run anywhere" 的实现方式。

.class 不能当保密手段。 它隐藏了原始文本，但字节码可以反编译。课件专门提了这点，因为"交付 .class 就安全"是个流传很广的误解。

两个命令的参数形式不一样，而且各有各的道理：

  • javac HelloWorld.java——编译器处理的是文件,所以要带扩展名;
  • java HelloWorld——启动器加载的是类,所以给类名，加 .class 反而错。

改完代码必须重新 javac,否则 java 跑的还是旧的 .class。

比记住命令更重要的：三类错误的分层。

错误类型暴露时机例子
编译错误javac 阶段漏分号、类型不匹配
运行时错误运行阶段除以零、数组越界
逻辑错误能跑但结果错求面积写成长+宽

分层的价值在于调试效率：看到问题先定位它在哪一层，再决定用什么手段。编译错误读编译器报错就行；运行时错误要看异常和程序状态；逻辑错误最隐蔽，只能靠测试和推理。混在一起瞎改是最慢的路径。

四、静态类型模型：这一讲的核心

Python 允许：

python
x = 0
x = "horse"

Java 直接拒绝：

java
int x = 0;
x = "horse";  // 编译错误

要理解静态类型，得先破除一个名字带来的误解："静态"说的是检查时机(运行之前),不是"值不能变"。 值随便变，类型不能变：

java
int age = 20;
age = 21;            // 合法：值变，类型不变
age = "twenty-one";  // 非法：String 与 int 不兼容

检查也不只发生在变量赋值上——参数传入、返回值、每个表达式的中间结果，编译器都会核对类型是否兼容。可以说类型是 Java 里所有代码实体的固有属性,这是和动态类型语言最本质的思维差异。

值得想一层的问题：这套约束换来什么?

  • 换来：大量类型错误在交付前暴露;IDE 能可靠地补全、跳转、重构(因为它静态地知道每个名字的类型);方法签名本身就是可读的接口文档。
  • 代价：写更多类型声明;初学语法负担重;不加泛型等机制时代码通用性差。

所以"Java 啰嗦"和"Python 自由"不是聪明和笨的区别，是把检查成本放在写代码时还是运行时的权衡。项目越大、参与的人越多，前置检查越划算——这和第二节里 HelloWorld 外壳的道理是同一条逻辑。

但静态类型的能力边界必须清楚：它保证"类型层面的操作合法",不保证逻辑正确，也不保证运行时不出错。 一个能编译的反例胜过背十条结论：

java
public static int divide(int x, int y) {
    return x / y;   // 类型完全合法
}
// divide(10, 0) 一跑就 ArithmeticException

表达式也有类型，而且会反直觉。 + 一侧是字符串就变成拼接，且从左向右结合：

java
System.out.println(5 + 10 + "!");   // 15!  先算加法，再拼接
System.out.println("!" + 5 + 10);   // !510 先拼成 "!5",再往后拼

两行结果不同，因为结合顺序决定了每个 + 先做加法还是先做拼接。这类题考试常出现，但背后的规则其实就一条：先看结合顺序，再看操作数类型。

几个零散的、容易记错的点，一并记在这：

  • String 大写(它是类),int/double/boolean/char 小写(基本类型);字符串双引号、字符单引号，"A" 和 'A' 是不同类型。
  • ^ 是按位异或，不是乘方;乘方用 Math.pow(2, 10)。
  • int 固定 32 位，范围 -231 到 231-1,溢出就是溢出，不会像 Python 那样自动扩精度。
  • 引用类型比较内容用 .equals();== 比的是"是不是同一个对象"(完整的引用模型后面讲)。

五、控制流：循环的正确打开方式是追踪

官方例子 HelloNumbers:

java
public class HelloNumbers {
    public static void main(String[] args) {
        int x = 0;
        while (x < 10) {
            System.out.print(x + " ");
            x = x + 1;
        }
        System.out.println();
    }
}

while 的语义一句话：每轮先算条件，true 执行循环体再回头，false 跳出。所以可能执行零次，也可能永不停止(忘了更新变量就是经典的死循环来源)。

语法本身没有新东西，这一讲真正想教的是方法：循环程序的本质是"条件—执行—状态更新"的循环，读循环的正确方式是逐轮追踪状态，而不是把整段代码当文字读懂。

配套练习(输出累计和 0 1 3 6 ... 45)很能说明问题：

java
int x = 0;
int sum = 0;
while (x < 10) {
    sum = sum + x;
    System.out.print(sum + " ");
    x = x + 1;
}

这里 x 和 sum 各代表一个状态：x 是"本轮加哪个数",sum 是"截至目前的累计"。把每轮的状态变化画成表，任何边界问题都无处遁形：

轮次x更新后 sum输出
1000
2111
3233
4366

反过来，while 的经典错误几乎全是状态管理出错：忘更新(死循环)、< 写成 <=(多一轮)、更新写在输出前(序列整体偏移一位)。这些错误靠"读懂代码"很难发现，靠画表一逮一个准。

另外两个 Java 特有的点：循环/条件表达式的结果必须是 boolean,不能用 0/1 当真假(这又是静态类型思维);单语句循环体虽然能省略花括号，但风格上应始终保留，否则以后加语句容易埋雷。

六、方法：签名即契约

java
public class LargerDemo {
    /** Returns the larger of x and y. */
    public static int larger(int x, int y) {
        if (x > y) {
            return x;
        }
        return y;
    }

    public static void main(String[] args) {
        System.out.println(larger(-5, 10));
    }
}

签名 public static int larger(int x, int y) 的每一段：可访问性、归属(类还是对象)、返回类型、名字、参数列表。在静态类型语言里，这一行就是方法和调用者之间的契约——输入什么类型、输出什么类型，编译器据此检查每一次调用。

围绕这份契约，有几个必须分清的概念：

定义 ≠ 调用，形参 ≠ 实参。 x、y 是方法内部的局部变量，每次调用时由实参的值初始化。所以同一个方法被不同值调用，互不影响。

return 是"给结果 + 立即结束"二合一。 这解释了为什么 if 里 return 之后，后面的 return 不会执行;也解释了为什么声明了 int 返回类型，每条可能走完的路径都必须有 return——少一条，编译器直接拒绝。

println ≠ return。 前者是副作用(往输出写东西),后者才把结果交给调用者。声明 int 却只打印、或声明 void 却 return 3;,都是初学者的高频错误。

"Java 只返回一个值"的准确含义:一次 return 给一个结果，但结果可以是数组或对象，里面装多少数据都行。所以"不能返回多个值"不构成实际限制。

最后，static 在这里表示"属于类、调用不需对象",和"不可变"没有任何关系——不可变是 final 的事。这个混淆非常普遍，值得单独记。

七、代码风格：工程性的最低要求

第一讲谈风格只有一条核心：代码首先写给人读，其次才给机器执行。 课程后半段项目规模上来之后，难读的代码会让调试成本失控。

落到可执行的几条：

  • 命名承载信息。 elapsedSeconds 之于 x,studentCount 之于 n。短名字不是原罪，小范围的 i 完全可以；标准是读者有没有因此丢失信息。
  • 重复是信号。 两段大体相同的代码通常意味着该抽方法。重复的真正危害不是长，是"改一处漏一处"。
  • 注释写意图，不翻译语法。 x = x + 1; // x 加 1 是负资产；命名到位时很多注释根本不必写。而且过时的注释比没注释更危险——它会误导。
  • Javadoc 描述对外行为,不写实现细节：做什么、参数是什么、返回什么。

八、这一讲的边界和后续

课程主页把 Lecture 1 标成 "Intro, Instance Variables",但实例变量实际属于 Lecture 2。这里只需要建立分类概念，不深入：

变量种类声明位置归属
局部变量方法内一次方法调用
实例变量类体内、无 static每个对象一份
类变量类体内、有 static类本身，全体共享

回头看就很顺：这一讲的方法之所以都能写成 static,正因为它们只依赖参数、不碰任何对象的状态。下一讲开始创建对象，static 的完整含义自然补上。

配套动作：Lab 01 装环境(Java/Git/IntelliJ),Homework 0A 补语法(if/else、for、字符串的 length/substring/charAt/equals,注意 substring 左闭右开)。学习方法上课件强调"预测—验证":跑任何示例代码前先手写预测输出，再编译对比——这比反复看视频有效得多。另外记住一个边界：IDE 的红色波浪线是 IDE 的分析提示，不是语言本身；能不能编译，javac 说了算。

总结：一张逻辑链

code
结构模型:代码装进类，main 是协议入口
   ↓
编译运行模型:javac 生成字节码，JVM 加载执行
   ↓ (编译器在编译期做的事)
静态类型模型:类型是所有代码实体的固有属性，运行前完成检查
   ↓ (检查的边界)
三类错误:编译 / 运行时 / 逻辑——静态类型只覆盖第一层

一句话压缩：Java 要求程序员在运行前显式说明代码结构和类型，编译器利用这些信息提前检查，再由 JVM 执行编译产物。 第一讲的所有"和 Python 不一样",都能从这句话推出来。
